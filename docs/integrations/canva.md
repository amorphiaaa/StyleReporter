# Canva template integration

The first Canva integration step is intentionally provider-free. The backend
already has a versioned mapping for the user-authored `ManualStyleReport`:
`signature-style-v1`. It converts report content into named text fields and
keeps image slots separate so local client assets can be uploaded later.

## Template setup

Create a Canva brand template and add autofill fields with the exact names
below. Use text fields for report copy and image fields for client photos.

The mapping uses fixed slots to keep the page layout stable:

- 5 items for normal lists, palette colours, silhouettes, accessories, and
  brands;
- 3 items for how-to-use principles, style-language anchors, moodboard items,
  and action-plan items;
- 4 outfit formulas and 4 style anchors;
- 6 accessory categories and 11 brand categories.

Core field names include:

```text
REPORT_TITLE
ALIGNMENT_SUMMARY
CURRENT_STYLE_1 ... CURRENT_STYLE_5
DESIRED_STYLE_1 ... DESIRED_STYLE_5
DISCONNECT
STYLE_LANGUAGE_SUMMARY
PALETTE_FOUNDATION_1_NAME
PALETTE_FOUNDATION_1_HEX
PALETTE_FOUNDATION_1_DESCRIPTION
PALETTE_FOUNDATION_1_WORKS_WITH
PRINTS_TEXTURES_INTRO
SILHOUETTE_OUTER_LAYERS_1_NAME
SILHOUETTE_OUTER_LAYERS_1_DESCRIPTION
OUTFIT_FORMULA_1_NAME
OUTFIT_FORMULA_1_OCCASIONS
OUTFIT_FORMULA_1_LOGIC
OUTFIT_FORMULA_1_STEP_1 ... OUTFIT_FORMULA_1_STEP_5
ACTION_1_TITLE
ACTION_1_BODY
```

Palette prefixes are `FOUNDATION`, `ACCENT`, and `PORTRAIT`. Silhouette
prefixes are `OUTER_LAYERS`, `BOTTOMS`, `TOPS_AND_KNITWEAR`, and `DRESSES`.
The complete field list is generated by
`signature_style_template_definition()`; this is the source of truth for
field names.

Image slots are:

```text
CLIENT_PORTRAIT
CLIENT_BODY_PROPORTION
CLIENT_GOOD_OUTFIT_1 ... CLIENT_GOOD_OUTFIT_3
CLIENT_NOT_ME_1 ... CLIENT_NOT_ME_2
CLIENT_INSPIRATION_1 ... CLIENT_INSPIRATION_3
```

Keep unused slots in the design with their default/empty state. The mapping
always emits empty text values for missing report items.

## Planned runtime flow

1. User saves the manual report in StyleReporter.
2. Backend validates the report and checks the template dataset.
3. Selected local assets are uploaded to the user's Canva library.
4. Backend starts an asynchronous Canva Autofill job.
5. The completed design URL is saved against the report and shown to the
   user.
6. User opens the design in Canva, makes visual adjustments, and exports it.

Canva Autofill works with existing brand templates and asynchronous jobs. The
integration must act on behalf of a Canva user; current Canva documentation
requires Enterprise access for the Autofill APIs, with a limited development
trial available in some cases. Verify this before implementing OAuth.

No Canva credentials, template IDs, or client assets belong in the repository.
